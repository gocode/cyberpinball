# Manual tests for milestone 1 (screens)

What the automated tests don't cover: the real hardware, the real keyboard and how Windows reacts. Each scenario is started from `lanceur.cmd` (double-click, or `.\lanceur.cmd <action>` in a terminal).

Before you start, run a detection (`ecrans` action) and write down the fingerprint and the "nom pour VPX" (name for VPX) of each screen. Scenarios 2 to 5 assume that a cabinet has been saved with the setup wizard (scenario 1).

| # | Scenario | How | Expected result |
| --- | --- | --- | --- |
| 1 | Setup wizard with the keyboard | `assistant` action. "Boutons" (Buttons) step: wait 20 s without touching anything (default keys kept), or see scenarios 70 onward. Then left / right Shift to change screen, 1 to confirm, Esc to skip an optional role, Backspace to go back, Ctrl+Q to quit. | The candidate screen blinks; the summary appears on the playfield; after confirming, `VPinballX.ini` is written in the sandbox (`ini` action). |
| 2 | Screens moved in Windows | Settings > System > Display: drag a screen somewhere else in the layout, Apply. Then `sync` action. | Only the `…Display` keys of the moved screens change; a backup appears in `backups` (`donnees` action). A second `sync` answers "à jour" (up to date). Put the layout back and run `sync` again. |
| 3 | Screen switched off or unplugged | Switch off the DMD screen (or unplug it), then `sync`. | Warning "DMD : l'écran … est introuvable" (DMD: screen … not found), without blocking. |
| 4 | Playfield screen missing | Switch off the playfield screen, then `sync`. | BLOCKING message; the file is not modified. |
| 5 | Scaling | Set a screen to 125% (Settings > Display > Scale), then `ecrans` and `sync`. | Detection shows "échelle 125 %" (scale 125%); synchronization warns that VPX locates screens in logical coordinates. Set it back to 100%. |
| 6 | Manual setting preserved | Add a `BallTrail = 0` line under `[Player]` in the sandbox `VPinballX.ini`, then repeat scenario 2. | The added line is still there after the correction. |
| 7a | Flipper edge | `assistant` action, choose the playfield, then left / right flipper buttons. | The playfield display rotates a quarter turn on each press; the "Flippers · vous êtes ici" (Flippers · you are here) strip runs along the chosen edge. Left or top side of a landscape image: yellow message "Start retourne l'écran dans Windows…" (Start flips the screen in Windows…), and "Start : retourner l'écran pour VPX" (Start: flip the screen for VPX) in the help. |
| 7b | Diagonal | Start on the right edge. | The suggested diagonal matches the screen (inches and cm); flipper buttons to correct it. After saving: `BGSet`, `ScreenWidth`, `ScreenHeight` in `VPinballX.ini` (`ini` action), and `CabinetAutofitMode = 1` in cabinet view. |
| 7c | Real framing on the cabinet | On the cabinet, run the wizard again with the real edge and the real diagonal, then launch two tables. | The whole table is visible, flippers near the bottom of the screen (5% by default), upright for the player, without any adjustment in the VPX editor. |
| 7d | Flip by the wizard | On the cabinet, player at the left edge of a playfield that Windows displays in landscape: `assistant` action, choose the playfield, rotate until the text reads upright, Start. | The playfield screen blinks, then the text stays upright for the player: "Écran retourné" (Screen flipped) and a 15 s countdown. The summary says "Flippers à droite de l'image" (Flippers on the right of the image), with no "à l'envers" (upside down) item; a table opens with the flippers on the player's side. Same thing for a player at the top of a Windows display set to portrait. |
| 7e | Cancel the flip | As in 7d, then Exit during the countdown. Start again without touching anything for 15 s. Start again and press Ctrl+Q. | Each time, the screen returns to its original orientation (check in Settings > Display); message "orientation d'origine rétablie" (original orientation restored), and Start then moves on to the diagonal without flipping. |
| 7f | Portrait seen from the side | If the cabinet allows it: Windows in "Portrait", player at the left or right edge of the image, Start. | Quarter turn toward landscape, text still upright for the player. Otherwise, Exit and report it: the direction of the quarter turn (`edgeAfterRotation`) needs fixing. |
| 6b | Managed key changed by hand | In the cabinet's `VPinballX.ini`, set `BGSet` to `0` (or change it in the VPX in-game menu), then `jouer` action. | Message "VPinballX.ini modifié à la main" (VPinballX.ini changed by hand) with the key and both values; nothing is overwritten. Start: the value stays and the key becomes editable in the VPX settings. Try again with Exit: Cyber Pinball's value comes back, and a backup is in `backups`. |
| 7 | Unattended demo | `demo` action (covers the screens for about ten seconds). | The screenshots of each step open in File Explorer; the demo file is shown in the terminal. |

**Trial on 10 real tables (scenario 33).** Download 10 archives as published (VPUniverse, VPForums), without renaming or unpacking them, covering a range of cases:

1. a recent VPW table (e.g. Attack from Mars, Medieval Madness);
2. a VPUniverse package with a numeric prefix ("1492939964_…") and a separate backglass;
3. a table whose title starts with an article (The Addams Family, The Getaway);
4. a mod ("Bigus MOD", "mod") of a table already in the list;
5. a title made by several manufacturers (Star Wars, Indiana Jones, Batman);
6. an electromechanical table (no ROM);
7. a ROM table whose ROM is shipped separately (ROM zip to add along with the table);
8. a table with PuP videos or DMD colors (Serum);
9. an original table (manufacturer "Original");
10. a 7z or rar archive.

Copy the 10 archives (and the separately shipped ROMs) into `<racine>\import`, then "Ajouter une table" > "Importer le contenu du dossier d'import" (Import the contents of the import folder), all in one go. For each table, record in a spreadsheet: the archive, the folder created, the VPS game selected (certain, chosen or none), the authors in the `.info`, what the doctor says after the addition, and whether the table starts (Start in the menu, one ball played, back to the menu). Expected:

- each folder is named "Title (Manufacturer Year)" according to VPS, the backglass carries the folder name and the ROM is in `pinmame\roms`;
- uncertain games only ask for one choice with the buttons, the others for none;
- the `.info` in each folder contains `Title`, `Manufacturer`, `Year`, `VPSId` (and `Authors` when the author is in the file names);
- the import folder is empty, the archives are in `trash\`;
- the doctor reports nothing blocking, and all 10 tables start without any file being touched by hand.

Any manual correction that turns out to be needed is a defect to report, with the exact name of the archive and of the files it contains.

Unattended demonstration (screenshots in `tmp\captures\vps`): `.\docs\demo-vps.ps1 -Run`, with empty files named after real tables.
