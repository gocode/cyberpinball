# Tests manuels du jalon 1 (écrans)

Ce que les tests automatiques ne couvrent pas : le vrai matériel, le vrai clavier et les réactions de Windows. Chaque scénario se lance depuis `lanceur.cmd` (double-clic, ou `.\lanceur.cmd <action>` dans un terminal).

Avant de commencer, faites une détection (action `ecrans`) et notez l'empreinte et le « nom pour VPX » de chaque écran. Les scénarios 2 à 5 supposent qu'une borne a été enregistrée avec l'assistant (scénario 1).

Puis Shift gauche / droit pour changer d'écran, 1 pour valider, Échap pour passer un rôle optionnel, Retour arrière pour revenir, Ctrl+Q pour quitter. | L'écran candidat clignote ; le récapitulatif s'affiche sur le playfield ; après validation, `VPinballX.ini` est écrit dans le bac à sable (action `ini`). |
| 2 | Écrans déplacés dans Windows | Paramètres > Système > Affichage : faites glisser un écran ailleurs dans la disposition, Appliquer. Puis action `sync`. | Seules les clés `…Display` des écrans déplacés changent ; une sauvegarde apparaît dans `backups` (action `donnees`). Une seconde `sync` répond « à jour ». **Essai sur 10 tables réelles (scénario 33).** Téléchargez 10 archives telles que publiées (VPUniverse, VPForums), sans les renommer ni les déballer, en variant les cas :

1. une table VPW récente (ex. Attack from Mars, Medieval Madness) ;
2. un paquet VPUniverse à préfixe numérique (« 1492939964_… ») avec backglass séparé ;
3. une table dont le titre commence par un article (The Addams Family, The Getaway) ;
4. un mod (« Bigus MOD », « mod ») d'une table déjà présente dans la liste ;
5. un titre que plusieurs fabricants ont fait (Star Wars, Indiana Jones, Batman) ;
6. une table électromécanique (sans ROM) ;
7. une table à ROM livrée à part (ROM zip à ajouter avec la table) ;
8. une table avec vidéos PuP ou couleurs DMD (Serum) ;
9. une table originale (fabricant « Original ») ;
10. une archive 7z ou rar.

Copiez les 10 archives (et les ROM livrées à part) dans `<racine>\import`, puis « Ajouter une table » > « Importer le contenu du dossier d'import », en une seule fois. Pour chaque table, notez dans un tableau : l'archive, le dossier créé, le jeu VPS retenu (sûr, choisi ou absent), les auteurs du `.info`, ce que dit le médecin après l'ajout, et si la table démarre (Start dans le menu, une bille jouée, retour au menu). Attendu :

- chaque dossier s'appelle « Titre (Fabricant Année) » d'après VPS, le backglass porte le nom du dossier et la ROM est dans `pinmame\roms` ;
- les jeux incertains ne demandent qu'un choix aux boutons, les autres aucun ;
- le `.info` de chaque dossier contient `Title`, `Manufacturer`, `Year`, `VPSId` (et `Authors` quand l'auteur est dans le nom des fichiers) ;
- le dossier d'import est vide, les archives sont dans `trash\` ;
- le médecin ne signale rien de bloquant, et les 10 tables démarrent sans avoir touché un fichier à la main.

Toute correction manuelle nécessaire est un défaut à signaler, avec le nom exact de l'archive et des fichiers qu'elle contient.

Démonstration sans opérateur (captures dans `tmp\captures\vps`) : `.\docs\demo-vps.ps1 -Run`, avec des fichiers vides aux noms de vraies tables.

# Tests manuels des plugins de VPX (backglass, PuP, DMD réel)

Prérequis : VPX installé, une table avec ROM, l'encodeur branché en mode clavier. Notez pour chaque bouton la touche affichée par l'assistant : c'est le relevé de l'encodeur, utile s'il faut le reprogrammer.
