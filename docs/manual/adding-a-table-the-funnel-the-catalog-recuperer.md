## Adding a table: the funnel, the catalog, "Récupérer", waiting list

System menu > "Tables" > **"Ajouter une table" (Add a table)** is the only entry for adding a table, whatever the method: you go in, then pick the method.
The online catalog (**"Trouver une table en ligne" (Find a table online)**) shows every game in the VPS database that can be played in VPX (2,370 on October 22, 2026, 960 of them with no ROM to find), its versions, and what it takes to play it on this cabinet.

- **The funnel** (`buildAddSource`, `app/src/library.ts`), with the cabinet buttons as with the mouse, in this order: **"Prêt à installer" (Ready to install)** (games whose received files are waiting to be installed: "Installer : <jeu>" (Install: <game>) opens the plan); **"Importer le contenu du dossier d'import" (Import the import folder's content)** (`<racine>\import`, filled from a USB stick, each item listed); **"Trouver une table en ligne" (Find a table online)** (the catalog); **"Reprendre un fichier téléchargé" (Reuse a downloaded file)** (Cyber Pinball's downloads, without downloading anything again), **"Choisir des fichiers…" (Choose files…)** and **"Choisir un dossier…" (Choose a folder…)** (Cyber Pinball's file picker, see [Downloads and file picker](downloads-and-file-picker.md#downloads-and-file-picker); or drag and drop onto the window, from anywhere); **"Depuis une autre installation…" (From another installation…)** (see below); **"Depuis un ami…" (From a friend…)** (see below); **"Récupérés et attendus" (Received and expected)** (the waiting list); **"Mises à jour des tables" (Table updates)**; **"Comptes des sites" (Site accounts)**.
  The menu entry carries a red dot when received files are waiting to be installed.
  The catalog screens come back to the funnel.
  A test (`packages/core/src/test/menu-paths.test.ts`) refuses any interface or documentation text that still cites these entries at the top level of the system menu.
- **From another installation** (`app/src/installation-import.ts`, core `packages/core/src/installation.ts`): in a PinUP Popper, PinballX, PinballY or plain VPX installation, a table does not have everything in a folder of its own.
  Its `.vpx` and backglass are in the tables folder, flat or each in its own subfolder (`Tables\X-Files Siggis Mod\X-Files (Sega 1997).vpx`), at any depth; its ROM, save, colours and sounds in VPinMAME (`roms\<rom>.zip` or unzipped `roms\<rom>\`, `nvram\<rom>.nv`, `altcolor\<rom>`, `altsound\<rom>`); its PuP-Pack in `PinUPSystem\PUPVideos`; its music in `VisualPinball\Music`; its media in `POPMedia\Visual Pinball X\<type>`, `PinballX\Media` or `PinballY\Media`, under the name the menu gives it.
  **The installation is recognised whatever its layout** (`findInstallation`): by walking up from the table to the root of the drive (VPinMAME, `VPinballX*.exe`, PinUPSystem, PinballX, PinballY; a `VPinMame` kept in a table's folder stays with that table); from what the menus say (Popper's `PUPDatabase.db`, opened read-only through `node:sqlite`: tables, media and ROM folders of each Visual Pinball emulator, each table's name and media name, its ROM; `PinballX.ini` and PinballY's `Settings.txt`: `TablePath`; their `Databases\<system>\*.xml`: each table's description); and from the registry (VPinMAME's `rompath`, `nvram_directory` and `vpxpath`, `app/src/installation-hints.ts`).
  Only a table kept under an established tables folder (named by VPX or a menu, or called "Tables") receives its parts: a `.vpx` downloaded elsewhere takes nothing.
  **Any `.vpx` chosen in such an installation** (through this screen, "Choisir des fichiers…" or drag and drop) brings what belongs to it (`installationCompanions`).
  Kept in a folder of its own (`tableHome`: under a tables folder without being one, and whose `.vpx` files are all versions of the same game), **that whole folder** replaces it in the import, subfolders included (sounds, another emulator's ROM, spare backglass, `.res` and `B2STableSettings.xml`, music); the other versions it holds are part of it only if they are ticked too (`ImportSource.exclude`).
  Otherwise, the files named like it next to it (`.directb2s`, `.ini`, `.pov`, `.vbs`, `.res`), or the only `.directb2s` whose name starts like its own.
  Then the ROM its script asks for (or that the menu gives when the script can't be read), in every form (zip, chip folder rebuilt as a zip, one level down as in `roms\_src`), its save, colours and sounds; the PuP-Pack under one of the names the plugin will load (`expectedPackNames`), failing that a `PUPVideos` folder with the table's title or whose name starts that title (`STRANGERTHINGS4` for "Stranger Things 4 LPE"), if it is the only one; the script's DMD folder (`ProjectFolder`); the music the script plays (`PlayMusic "Akira\…"`, filed in `music\Akira`); and the media under every name of the table (`tableMediaNames`: the `.vpx` name, Popper's name, PinballX and PinballY's description, the names of the other versions in the same folder), failing that under its title alone if no other table has it.
  Logs (`.log`), crash reports (`crash.dmp`, `crash.txt`), VPX's cache and the original archive (a `.zip` that is not a ROM, outside a `roms` folder) are never brought in, from an installation or from a chosen folder (`classifyFile`, `isRomZip`).
  Each of these parts enters the add plan, attached to its table (`ImportSource.owner`).
  The plan shows them under "Repris de l'installation d'origine" (Brought in from the original installation): what was found, and what the script expects that the installation lacks ("absent de l'installation : PuP-Pack « … »", missing from the installation: PuP-Pack “…”).
  Everything is copied; the original installation does not change.
  The **"Reprendre une table d'une autre installation" (Bring in a table from another installation)** screen opens straight onto the installation found in the usual places (`C:\vPinball`, `D:\Visual Pinball`, `C:\PinballX`, `C:\PinballY`…, and the one the registry names, `knownTableInstallations`), otherwise its folder is chosen (the root, its Tables folder or PinUPSystem, `findInstallation`).
  It lists its tables one by one, at any depth, and those Popper knows elsewhere.
  When the original menu says which ones it plays, only those are shown at first, each with its lists: Popper playlists, made by hand (`PlayListDetails`) or automatic (the `PlayLists.PlayListSQL` query on `Games`, run on the database opened read-only; the recently-added list, bounded by `LIMIT`, and hidden lists don't count), or the enabled tables (`enabled`) of PinballX and PinballY.
  An entry whose file has gone is matched by the file name (table moved).
  "Montrer toutes les tables du disque" (Show every table on the drive) adds the others (backup copies, old versions), "Cocher la liste « … »" (Tick the “…” list) ticks all of a list's tables at once.
  Each table is shown with "Déjà dans la borne" (Already on the cabinet), the backglass and the number of media found; Start ticks or unticks a table, then "Reprendre les tables cochées" (Bring in the ticked tables) opens the plan.
  Nothing is downloaded, nothing is brought in wholesale.
  Cyber Pinball's own root is never taken for another installation.
  A folder chosen alone keeps the kind its parent folder says (`PUPVideos\<pack>`, `altsound\<rom>`, and `altcolor\<rom>`, filed in `serum\<rom>` or `vni\<rom>` according to its files, `classifyDir`).
  Tests: `packages/core/src/test/installation.test.ts`, and `installation-dispositions.test.ts` for each layout met in practice (a folder per table with what it really holds, two versions in one folder, a folder grouping several games, PinballX and its descriptions, Popper with a tables folder under another name, unzipped ROM, the script's music).
- **From a friend** (`app/src/friends-menu.ts`, `buildAddFromFriend`): the list of friends, those who have tables missing from the cabinet first ("<n> à prendre" (<n> to take), "12 tables, dont 3 absentes de votre borne" (12 tables, 3 of them missing from your cabinet)), then online friends whose library is on its way or has nothing new; an offline friend (or one the Windows firewall makes unreachable) is greyed out with its reason and Start leads nowhere.
  Start on a friend opens their library (see [Friends: the cabinet network](friends-the-cabinet-network.md#friends-the-cabinet-network)) with their tables **missing from your cabinet first**, the cursor on the first one; a table is taken from there as from the friend's page ("Récupérer toute la table" (Get the whole table), ROM and PuP-Pack unticked until the rights attestation, add plan before installing).
  "Retour" (Back) returns to the list of friends, then to "Ajouter une table".
  Tests: `friends-menu.test.ts`.
- **Quick install** ("Installation rapide", at the top of a game's page, and on a version's "Ce qu'il faut" (What it takes)): the recommended version, in one go.
  The essentials to fetch and the recommended backglass (`quickNeeds`, `packages/core/src/acquisition.ts`) enter the waiting list and are fetched one after the other, the essentials (the table, the ROM) first: each page opens by itself in the "Récupérer" window as soon as the previous file is received; once everything is there, the window closes and the plan opens, the game already chosen.
  The backglass never holds the plan back: as soon as the essentials are received, "Installer sans attendre" (Install without waiting) closes the window and opens the plan, the backglass staying awaited in the list.
  Window closed along the way: "Continuer l'installation rapide" (Continue the quick install) reopens the next page; "Arrêter" (Stop) keeps what was received.
  A version with an essential that has no live link says so and is not started.
  While a file is arriving, its part shows it itself, on top of the message at the top: "Téléchargement en cours" (Downloading) badge, green bar and figures (percentage, amount, rate) on its card, on its line of the waiting list and in the game parts of an installed table; size not announced, hatched bar.
- **VPinMediaDB media when adding**: the plan of a new table recognized in the VPS database (catalog, import folder, picked or dropped files) has a "Médias de VPinMediaDB, après l'installation" (VPinMediaDB media, after the install) section: what VPinMediaDB has for this game (wheel, playfield, backglass, full DMD, flyer, music, the variant "Chercher les médias" picks), the size, and the license warning.
  Kept by default; "Médias de VPinMediaDB : oui / non" (VPinMediaDB media: yes / no) leaves them out.
  After "Installer" (Install), only the missing ones are downloaded (none is replaced), source noted in the `.info`, and the table check counts them ("Ajouté avec la table", Added with the table).
  This is the original "one-click" add, a table and its media from what you have, found again.
  Index unavailable: the section says so, the table installs alone.

- **What Cyber Pinball does not do**: download on the user's behalf.
  Nearly all VPS links lead to forum pages (vpuniverse.com, vpforums.org…) that require an account and whose terms forbid bots and rehosting; no manufacturer allows its ROMs to be distributed for emulation.
  The warning is shown on first use (accepted once, with the date stored in `<données>\acquisition.json`).
- **Catalog**: twelve games per page, with their VPS thumbnail, their type, their versions and their ROM; "Chercher un titre…" (Search a title…) matches title, initials and ROM name, like the media search; thumbnails arrive in the background (six at a time, those of the next page prepared ahead): the page shows at once and the keys respond while they arrive; "Page suivante" (Next page) and "Page précédente" (Previous page) stay in place, greyed when there is nothing on that side.
  "Filtres et tri" (Filters and sorting) opens the filters screen: one line per filter, always the same and in the same place (on the cabinet, nothing moves under the cursor); Start on a line opens its choices, each with its number of games, the other filters kept, the cursor on the current choice; Start on a choice keeps it and goes back to the filters:
  - **Jeux** (Games): all, no ROM to find, solid-state, electromechanical, original creations;
  - **Fichiers** (Files): what the game offers for download, with a live link: backglass (`.directb2s`), ROM, PuP-Pack (one included with a table counts), remastered sounds, DMD colors, music, topper, point of view, a VR version, or media on VPinMediaDB (from its index, downloaded the first time this filter is used);
  - **Site**: where the table, or the files of the "Fichiers" filter, is downloaded: vpuniverse.com, vpforums.org, pinballnirvana.com, or no account (Google Drive, MEGA, Dropbox, GitHub, the game code Stern publishes…; a YouTube video or an IPDB page does not count);
  - **Sur la borne** (On the cabinet): not installed yet (default), installed or not, already installed;
  - **Tri** (Sort, first): most popular first (default), newest first, or by title (during a search, the order is the search's, and the line stays, greyed).
    Popularity: since there are no download figures for the whole database (VPS has none, the forums only give them file by file), the number of different authors who made something for the game (versions, backglasses, PuP-Packs, sounds, colors, rules, videos), then the number of those files (`popularity()`): The Addams Family, Attack from Mars, Medieval Madness first; a series of variants by one author (NFL, one table per team) does not get ahead.

  The chosen filters and sort are kept from one visit and one start to the next (`<data>\catalogue-filtres.json`, `loadCatalogChoice()`); the search is not.
  "Effacer les filtres" (Clear the filters) goes back to the original values (greyed when already there); "Voir les <n> jeux" (See the <n> games) (or Exit) goes back to the catalog.
  Every game comes from the VPS database.
  The games of each filter are computed once and kept (about forty combinations): the screen redraws on every key without recomputing anything; one computation takes about twenty milliseconds over the 2,600 games (half a second before 12/11/2026, the title sort building a new comparer for every comparison).
  Code: `catalog()`, `supportFiles()`, `linkOnSite()` in `packages/core/src/acquisition.ts`.
- **A game's details screen**: its VPX versions, the **recommended** one first (not a MOD when possible, VPW preferred, the most recently updated, with a working link; the reasons are spelled out), then the others, with their particulars (MOD, VR, nFozzy, Fleep, what they include), the date and the site.
- **Choosing a file: the file gallery** (`app/src/file-gallery.ts`, core `packages/core/src/sitefiles.ts`): every list of files to choose from is a gallery, never a list of names.
  This covers a game's versions; "<part> : au choix" (<part>: pick one) on "Ce qu'il faut" (What it takes) (backglass, ROM, PuP-Pack, colours, sounds, music, topper, point of view); the same from the parts of an installed game; and "Voir les <n> au choix" (See the <n> to choose from) on "Ce qu'il manque pour jouer" (What is missing to play), offered as soon as the VPS database knows several files for a step.
  Each tile, three per row, shows:
  - the **preview** in the shape of what it shows (upright table, 4:3 backglass, 4:1 DMD colours, `FILE_PREVIEW_ASPECT`): the VPS database thumbnail, otherwise the screenshot the author uploaded to their site;
  - the name (authors and version, or the ROM name), the state (Installed, Recommended, Received, Awaited) and at most two particulars (2Screens, FullDMD, MOD…);
  - the **popularity** ("1 324 téléchargements · 5/5", 1,324 downloads · 5/5), then the date and the site.

  Under the gallery, the detail of the chosen tile: authors and version, rating and number of reviews, views, size, account required, category on the site, particulars and comment, and for a version, why it is recommended.
  "Trier : …" (Sort: …) goes from the screen's order ("écrans de la borne", cabinet screens; "conseillée d'abord", recommended first; or the date) to popularity (most downloaded first, unknown ones last), then to the date; the chosen order is kept from one screen to the next during the visit.
  The date is the VPS database's when it gives one: the order does not move when the file pages arrive.
- **Site file pages** (`app/src/site-files.ts`): the VPS database gives neither downloads nor rating, and no thumbnail for ROMs, PuP-Packs, colours and sounds.
  When a gallery opens, Cyber Pinball reads each file's page, as a visitor, with the cookies of the "Récupérer" (Get) session, without showing it or running its scripts, four at a time; each page read fills its tile:
  - **VPUniverse**: its schema.org description (downloads, views, rating out of 5 and number of reviews, author, version, date, size, category, screenshots);
  - **VPForums**: the "File Information" block, the stars and votes under the title, the author's screenshot (never another file's thumbnail).

  Pages are kept for a day in `<downloads>\sites\fiches.json` (a page that says nothing or a network failure is read again an hour later), screenshots in `sites\apercus`.
  A page that has gone (404) carries "Retiré du site" (Removed from the site); another site (Dropbox, MEGA, Google Drive) "ne dit ni téléchargements ni note" (gives neither downloads nor rating); a page received but unreadable is reported in the log ("Fiche de vpuniverse illisible").
  `sitefiles.test.ts` reads both witness pages (`packages/core/test-pages/vpuniverse-fiche.html`, `vpforums-fiche.html`) and rejects any list of VPS files to choose from built outside the gallery.
- **What it takes**, worked out without downloading anything, from the cabinet's screens and the ROMs already there: the table; the backglass (`.directb2s`), unless it comes with the table or the cabinet has no backglass screen, with the ones that suit its screens first; the ROM, unless the game needs none or it comes with the table ("déjà sur la borne" (already on the cabinet) if the library or a table has it); then, optional, PuP-Pack, remastered sounds, DMD colors (if there is a display), music, topper (if there is a topper screen), point of view.
  Each line gives its site and whether an account is needed.
- **"Récupérer" (Fetch) window** (Start on a line): the file's page opens under a Cyber Pinball banner that reminds you what to download (game, version, authors, ROM), with "Précédent" (Back), "Retour à la fiche" (Back to the page), "Ouvrir dans mon navigateur" (Open in my browser) and "Fermer (Échap)" (Close (Esc)).
  You sign in and download yourself, with keyboard and mouse; Cyber Pinball clicks nothing, fills in nothing and sees no password (separate session, `persist:acquisition`, like a browser).
  Each downloaded file is stored in `<racine>\downloads\acquisition` and matched to what was expected through the page it came from.
  Close, Esc or Alt+F4 does not lose the page: the window's history is kept (`navigationHistory`), and reopening it for the same starting page ("Chercher sur le web…" (Search the web...) for the same media, for instance) picks up the page where you were, "Précédent" (Back) included ("Repris là où vous en étiez", Back where you left off).
  Esc, the key you press out of habit to close an enlarged image or after a screenshot, used to close the window and start again from the starting page.
  A video of the page in full screen keeps Esc for itself (it leaves full screen).
  Minimized (Windows+D, Windows+M), the window comes back when reopened.
  The cabinet's Exit (key or joystick button) closes it too, even while typing in the page.
  While it is open, no cabinet window comes in front of it: any other Cyber Pinball window that takes the focus (click, joystick button, script reading) hands it straight back; in 0.1.3-essai.2, the first click in the page brought the backglass in front.
  - **Banner sized to the screen**: the banner is written in reference pixels (a 1,080 px short side, `--u` in `app/renderer/acquire.css`), like the menu: it follows the screen it covers, at 1366 × 768 as in 4K, and no text in it goes below 20 px (the game at 30, what is expected at 22, everything else at 20: buttons, host, status, screen line, engines, video page, download lines).
    Reference heights: 132 (164 with the line about the chosen screen), plus 76 for the search line, 62 for a video page, 48 per download and 12 below; the main process makes the same count, multiplied by the screen's scale, and places the site's page right below (`BAR`, `barHeight`, `app/src/acquire-window.ts`).
    On a narrow screen (portrait, 4:3, 5:4: less than 1,500 wide for 1,080 high), the four buttons no longer fit beside the rest: they move below it and share the width (196 high, 228 with the screen line; `html.narrow`), and a download's text (size, speed, time left) takes room from the bar.
    Up to 0.1.4-essai.21, the banner was in fixed px: 96 px high and texts of 12 to 16 px whatever the screen size (6 to 8 reference px on a 4K screen at 100 %).
    A test now refuses any font size in fixed px in the screens' stylesheets (`plancher-textes.test.ts`).
  - **Screen and pointer**: the page is read and driven with the mouse.
    Its screen is chosen in **"Écran du navigateur intégré" (Built-in browser screen)** (system menu > "Borne" (Cabinet) > "Configuration de la borne" (Cabinet configuration) > "Configurations de la borne" (Cabinet configurations) > the configuration; shortcut in "Comptes des sites" (Site accounts)): **Automatique** (Automatic), or one of the cabinet's roles (Playfield, Backglass, DMD, Topper: only those the configuration has).
    The choice is stored in the configuration (`browserScreen` in `cabinet.json`, `packages/core/src/browser-screen.ts`) by role: it follows the screen found by its fingerprint, even when Windows renumbers it, and the full wizard keeps it.
    Each choice has its preview line, highlighted when it is pointed at with the buttons or the mouse: the screen (name, size), landscape or portrait, which role it is shared with (backglass and DMD on the same screen), upright facing the player or, for the playfield lying flat, "the page and the mouse go sideways there"; for Automatic, the screen it gives right now.
    It applies to every "Récupérer" window (catalog, waiting list, site accounts, site media, web search), from the next opening.
    The chosen screen is not connected: the window takes the automatic screen, and one more orange line in the banner says so ("DMD is not connected, opened on Backglass (automatic)"); the turned playfield remains possible if chosen, and the same line warns that the page and the mouse go sideways there.
    **Automatic**, the behaviour from before the setting, is the screen where the mouse moves the same way as the picture (`readingScreen`, `packages/core/src/layout.ts`): the playfield if the menu is not turned there (desktop, cabinet where Windows follows the screen), otherwise the largest of the menu's other screens, the backglass first; on the cabinet, the page landed now on the DMD, now on the backglass, hence the choice.
    On a cabinet whose playfield lies flat and turned (flippers on the left or right of the Windows picture, which VPX corrects by turning its rendering), the page used to open on Windows' main screen, the playfield: sideways for the player, with a mouse moving at right angles to their hand, which vanished as soon as it crossed onto another screen, where the menu's windows hide the pointer.
    On opening, the pointer is brought to the middle of the window if it is not there already (`SetCursorPos`, `setCursorPosition` in `packages/win-displays/src/windows.ts`).
  - **Download progress**: while a download of the session is in progress, the banner gives it a line, below its buttons: the file name, a thin bar (signal green on teal), the percentage, then "48.2 MB of 312 MB · 3.1 MB/s · about 1 min", and "Annuler" (Cancel).
    **Size the site does not announce** (file served compressed or in chunks, common on forums): Cyber Pinball reads it on the page the download starts from, where the site shows it ("Size 212.6 MB" on vpuniverse.com, "File Size 40.81MB" on vpforums.org; on a page with several files, the size written next to the file's name; a "Size", "Taille" or "File Size" label right against the size, otherwise nothing), read at each page loaded, in the window or in a hidden view (`PAGE_SIZE_PROBE`, `expectedSizeFromPage`, `packages/core/src/transfer.ts`).
    The line then says "48 % · 2,0 Mo sur environ 4 Mo · 884 ko/s · quelques secondes" (48% · 2.0 MB of about 4 MB · 884 KB/s · a few seconds), bar included; 99% at most before the end, and a size exceeded by more than 3% is dropped.
    Neither the site nor its page gives it: "1,6 Mo reçus, taille non annoncée · 682 ko/s" (1.6 MB received, size not announced · 682 KB/s), no percentage, and the bar stays an empty dotted track (in 0.1.3-essai.5, a sliding segment looked like a half-full bar and said nothing).
    Menu notices, media proposals and VPinMediaDB downloads put the percentage first ("15 % · 48,2 Mo sur 312 Mo · …").
    Paused or interrupted: the line turns orange and says so.
    The speed is smoothed over a few seconds and shown after one second of measurement; the time left is rounded ("a few seconds", "about 25 s", "about 4 min", "about 1 h 20 min") so it does not jitter (`packages/core/src/transfer.ts`, `formatTransfer`).
    Every download of the session has its line, those of the visible page as well as those started without a window (site media), while the window is open; closed and reopened, it finds them again.
    Beyond three, two lines and a summary of the others ("And 2 more: 8.9 MB · 1.3 MB/s").
    The banner grows by one line per download and the site's page moves down by as much.
    Downloads are sampled four times a second, not on every packet; the menu (catalog and waiting-list notice), media proposals and VPinMediaDB downloads say the same thing, at most twice a second.
    **Cancel**: with the mouse, or with the cabinet buttons: Start points at the latest download (its line is highlighted, "Start again: cancel · flippers: another one · Exit: keep"), the flippers pick another one, Start again cancels it within six seconds; Exit (or Esc) gives up without closing the window.
    In the page, Start only counts outside a text field, and Enter, the arrows, Space and Tab stay with the page.
    The cancelled file is deleted and the banner says so ("Téléchargement annulé : …" (Download cancelled)); at the end, "Reçu : …" (Received) as before.
- **Waiting list** ("Récupérés et attendus" (Received and expected), in the funnel, the catalog and "Ce qu'il faut"): what is being fetched, game by game, "Attendu" (Expected) or "Reçu" (Received).
  A file downloaded in your own browser is found through "Surveiller Téléchargements : oui" (Watch Downloads: yes) (the Windows Downloads folder, only while something is expected; a file still downloading, `.crdownload` or `.part`, is ignored) or through "Chercher dans Téléchargements" (Search Downloads); it is matched by its name (zip named after the ROM, `.directb2s`, game name) and left where it is.
- **Received file filed by its nature**: before it is filed, each received file is recognised from its extension and, for an archive (zip, 7z, rar), from what it contains, listed without unpacking it (`tar -tf`): a table (a `.vpx`, or an archive containing one), a backglass (`.directb2s`), a ROM (a `.zip` of chip files, with no folder), a PuP-Pack (`.pup` files), remastered sounds (`altsound.csv`), DMD colours (Serum, VNI), music, a point of view, a topper, or **menu media** (images and videos, no `.vpx`).
  It goes to the **game part** its content says, whatever item was expected: a PuP-Pack downloaded from the table's page, with the "Récupérer" (Get) window open for the table, goes to the game's "PuP-Pack" part (the one that was expected, or a part **added** to the game for it: the VPS file of the same page gives its name, otherwise the file name), and the table stays expected; the message says so.
  The game must be certain: the window was open for it, or the file comes from the page of one of its items.
  A **complete archive** (table, backglass, ROM, PuP-Pack together) fills at once every part it brings: those that were expected separately no longer are ("apporte aussi : …", also brings, on the item's line, "Fourni", Included, on "Ce qu'il faut", What it takes).
  Without a certain game (nothing expected matches it), the file is **kept aside** and the "Fichier reçu à vérifier" (Received file to check) screen asks where to file it.
  An unreadable archive is taken without checking, and the line says so.
  Getting an already received item again **replaces** it: the old file is kept aside.
- **Fixing the waiting list**, with the buttons as with the mouse: each item is a line to choose (Start or click) that opens its screen: state, received file (size, date, where from), recognised content, what it expects.
  For a received item: "Réaffecter à : …" (Reassign to: …) (the game's item the file fits, if there is one), "Vider l'élément" (Clear the item) (it is expected again, the file is kept aside), "Remplacer par un autre fichier" (Replace with another file) (kept aside, received in `downloads\acquisition`, arrived in Downloads over the last month, fitting ones first; or "Rouvrir la page pour le télécharger de nouveau" (Reopen the page to download it again); or a file dropped on the window), "Réaffecter à un autre élément" (Reassign to another item) (fitting ones first; an item already received keeps its previous file aside), "Vider, fichier à la corbeille" (Clear, file to the trash).
  For an expected item: "Rouvrir la page" (Reopen the page), "Choisir un fichier déjà téléchargé" (Choose a file already downloaded), "Ne plus l'attendre" (Stop waiting for it).
  Everywhere, "Retirer tout le jeu de la liste" (Remove the whole game from the queue): keep the received files where they are, or put them in the trash.
  Assigning by hand a file that does not fit asks for confirmation ("Ce fichier ne convient pas", This file does not fit); assigned anyway, it is noted (`received.forced`): it is never redirected automatically and blocks nothing.
  "Le garder de côté" (Keep it aside) is noted the same way (`kept`).
  Nothing is ever deleted: the trash is Cyber Pinball's (`<racine>\trash\… Liste d'attente`).
  Files without an item are listed apart, "Reçus sans élément" (Received, not assigned) (`strays` in `acquisition.json`).
- **Repairing what is already there**: at startup, when the waiting list opens (and "Ce qu'il faut", What it takes, and before installing), the content of received files not noted yet is read once and noted in `acquisition.json` (`received.content`), then each file is put back in the part it belongs to, without asking (`repairWaitList`): a file filed in a part that is not its own (a PuP-Pack in "Table") moves to its own, and the item is expected again; a file that came from the page of another item of the same part (two versions of a table) goes back to it, and the origin recorded in the installed table's `.info` follows; a file kept aside whose game is certain (it comes from the page of one of its items) becomes a part of that game, **installed** if the table already has it (a PuP-Pack put by hand into `pupvideos`), otherwise received and to install.
  A message says what was filed.
  What was chosen by hand (assigned anyway, deliberately kept aside) is left alone.
  A file that is gone becomes "À corriger" (To fix).
  No need to edit `acquisition.json` by hand.
- **Installation**: "Installer : <jeu>" (Install: <game>) opens the usual add plan with the received files, the VPS game already chosen; nothing moves until "Installer" (Install), then the doctor checks the table.
  A file **to fix never blocks** the rest: the plan leaves it aside ("PuP-Pack à corriger à part", PuP-Pack to fix separately), and only a game where everything is to fix opens the item.
  What is fetched for an installed table ("Ce qu'il manque pour jouer", What's missing to play, "Parties du jeu", Game parts) all goes to it: the plan targets its folder (`PlanOptions.target`).
  The origin is recorded in the `.info` (`CyberPinball.source`: VPS game and file, version, authors, page, date); the copies in `downloads\acquisition` are deleted, the files in Downloads stay.
- **Table updates** (in the funnel): a table whose VPS file has a newer version, according to its recorded origin or, without one, according to the author and version written in the table; Start opens what is needed for the new version.
- **Site accounts** (in the funnel): vpuniverse.com, vpforums.org, pinballnirvana.com and pinsound-community.org, each "Connecté" (Signed in, with the date until which the sign-in is kept), "connecté pour cette fois seulement" (signed in for this time only) or "Pas connecté" (Not signed in), read from the cookies of the "Récupérer" session, all subdomains included.
  "Se connecter" (Sign in) opens the site's sign-in page in the "Récupérer" window: you enter your own account there and tick "Remember me"; the sign-in is then kept from one start to the next, as in a browser (about 3 months on vpuniverse.com, one year on pinballnirvana.com).
  "Se déconnecter" (Sign out) deletes that site's cookies and nothing else.
  Cyber Pinball neither sees nor keeps any password.
- **Block ads** (a setting in "Comptes des sites" (Site accounts), on by default): the built-in browser ("Récupérer" window, free search, YouTube) removes ads, with Ghostery's engine (`@ghostery/adblocker`) and the uBlock Origin and EasyList filter lists.
  Three levels, as in uBlock: requests to ad servers are cancelled, ad slots hidden, and the lists' small scripts ("scriptlets") run in the page before its own scripts, the only way to remove YouTube ads, which come from YouTube's own servers (`app/src/adblock-scriptlets-preload.ts`, a synchronous request at the start of the document).
  A page's scriptlets go out as a single script, each in its own function with shared tools (`combineScriptlets`): run one after the other, those that carry the same tools got in each other's way ("Identifier 'JSONPath' has already been declared", then an endless loop) and YouTube stayed blank.
  Pages of the table forums (vpuniverse.com, vpforums.org, pinballnirvana.com, pinsound-community.org) are never filtered: a hidden button or a blocked script would break the download there.
  The lists are kept in `data\adblock\filtres.bin` and fetched again once a day, in the background; on a first start offline, nothing is blocked and the setting's detail says so.
  YouTube changes its ads often: an ad that gets through again is fixed by the lists, fetched every day, not by the code.
  The setting applies from the next page (`adsShown` in `acquisition.json`).
  Code: `app/src/ad-blocker.ts` and `packages/core/src/adblock.ts`, test `packages/core/src/test/adblock.test.ts`.
- **What the built-in browser refuses**: what it cannot serve on a cabinet, where any Windows window would open under its full-screen displays (PinCab, 10/11/2026: Google's offer to sign in with a passkey often crashed the application).
  **WebAuthn** (passkeys, security keys, Windows Hello, nearby phone) is removed from pages and their frames (`disableBlinkFeatures: 'WebAuth'`): the page does not find it and offers the password; a request made without checking is refused at once (`NotAllowedError`, `app/src/acquire-page-preload.ts`).
  **Permissions**: only those that open nothing and touch no device (video full screen, copy to the clipboard, audio output choice, storage access, `PAGE_PERMISSIONS`); camera, microphone, location, notifications, MIDI, opening another application, screen capture, clipboard reading, files are refused (Electron granted everything until then).
  **Devices** (HID, USB, serial, Bluetooth): the choice is cancelled without a window (otherwise Electron took the first Bluetooth device around).
  Each refusal is logged once per site in `erreurs.txt` ("demande refusée (media) de …").
  A page that crashes is logged, reloaded once, and the banner says so.
  Code: `app/src/acquire-window.ts`; test: `packages/core/src/test/saisie-robuste.test.ts`.
- **Always a way out** (PinCab, 10/11/2026: "all screens black", the Task Manager was needed): the joystick's Exit button is read by "Récupérer" whatever window is in front; with no Cyber Pinball window in front (a Windows window took it, the page crashed), it still closes, and **held two seconds** it force-closes, frozen page included ("fermeture forcée" in `erreurs.txt`).
  A Windows window that takes the foreground (dialog, Task Manager) comes in front of "Récupérer", which gives up its always-on-top and takes it back with the focus (`frontMove`, `packages/core/src/front-policy.ts`).
  A page that no longer responds has its renderer stopped after 8 s, then is reloaded.
  Any Cyber Pinball window whose renderer crashes, or freezes for 15 s, is reloaded instead of staying black (`reviveCrashedWindows`, `app/src/uncaught.ts`); a screen left under its black veil alone for more than 4 s outside a game gets the menu window back in front (`veilAloneDue`).
  On a dedicated cabinet, the supervisor reads the pulse Cyber Pinball writes every 2 s (`data\logs\pouls.txt`); with no pulse for 45 s, it stops and relaunches it (`pulseStale`).
  Each time, an entry in `erreurs.txt`.
  Tests: `sorties.test.ts`, `saisie-robuste.test.ts`.
- **No application menu** (`app/src/app-menu.ts`, called at the top of `main.ts`): with no menu set, Electron sets its own, invisible in frameless windows but whose shortcuts stay active (Ctrl+A, Ctrl+R, Ctrl+W, Ctrl+Shift+I…).
  On 10/11/2026, on the PinCab, the full text typed from the phone (Ctrl+A then the text) brought down the whole of Cyber Pinball: Ctrl+A not handled by the page bubbled up to the default menu’s “Select All”, which calls `isFocused()` on every content, and on a hidden offscreen view (the media converter, background page reads) that check reads a null pointer in Electron (`aura::Window::GetToplevelWindow`).
  Proven by the PinCab’s Crashpad report symbolised with Electron 44.5.1’s symbols, and reproduced identically.
  Field editing shortcuts do not depend on it on Windows.
  **Google sign-in page**: never opened in “Get” (Google refuses the built-in browser there); a “Sign in” button, a redirect or a direct opening are stopped before any request, and the banner offers “Sign in to YouTube” (with Edge), which closes the window and opens the Juke-box account screen (`isGoogleSignIn`).
  **Windows permission requests** (dedicated cabinet, firewall, Kinect driver): the request shows on the secure desktop, where Windows refuses any simulated answer, so the cabinet buttons too.
  Each is announced beforehand by a screen (`app/src/uac-confirm.ts`, “Plus tard, au bureau” (Later, at the desk) selected by default, “Alt+O for Yes, Esc for No”), and is no longer waited for beyond 3 minutes (`ELEVATION_WAIT_MS`).
  Safeguard: `sorties.test.ts` lists the elevations.
  Tests: `saisie-robuste.test.ts`.
- **Juke-box YouTube account: sign-in with Microsoft Edge** (`packages/core/src/youtube-account.ts`, `app/src/youtube-account.ts`, `app/src/edge-login.ts`): Google refuses sign-in in the built-in browser, and a link through the API would require every user to have a Google Cloud project. “Sign in to YouTube” therefore opens a real Edge (present on every Windows 10 and 11, nothing to install) with a profile kept for the Juke-box, `<root>\data\edge-youtube`, as an app window placed on the screen chosen for browsers (“Built-in browser screen” of the configuration; in automatic mode, never a rotated playfield), on top on that screen.
  While signing in, Edge has no debugging port and no automation flag: to Google, it is an ordinary Edge.
  The phone remote is its mouse and keyboard through Windows (`SendInput`, `typeText`, `pressKey`, `mouseClick` in `win-displays`), and so are the cabinet buttons (flippers Shift+Tab and Tab, Start Enter, Exit closes Edge).
  Once Edge is closed, Cyber Pinball starts it again with no window (`--headless=new --remote-debugging-port=0`, on 127.0.0.1) and asks for its cookies (`Storage.getCookies`): Edge decrypts them itself.
  Only YouTube and Google cookies are taken (a new profile signs itself in to the Windows Microsoft account: those cookies are left out). yt-dlp gets them through a Netscape file (`--cookies`) written for a single call then deleted, for the list of the account’s playlists (`feed/playlists`, “Liked videos” and “Watch later” included) and reading a private playlist; the second reading and the downloads go without.
  No cookie nor file path in the log. “Sign out” deletes the profile.
  Testing: `CYBERPINBALL_EDGE_FAUX` (sandbox only) replaces Edge with a fake demo Edge.
  Tests: `youtube-account.test.ts` (arguments, sorted cookies, service with a fake Edge).
