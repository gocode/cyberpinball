## Game parts

A game is made of **parts**: the table (`.vpx`), the backglass (`.directb2s`), the ROM, the PuP-Pack, the DMD colours (Serum, VNI), the remastered sounds, the music, the point of view (`.pov`), its own settings (`.ini` named like the table), the topper and the menu media.
The same parts are used everywhere: the waiting list (`NeedKind`, `PART_KINDS` in `packages/core/src/acquisition.ts`), the page of an installed table (`GAME_PARTS`, `installedParts` in `packages/core/src/gameparts.ts`) and Downloads.

- **On reception**: each file goes to the part its content says, added to the game if needed, several parts at once for a complete archive; a file of another nature never blocks installing what is ready (see [Adding a table](adding-a-table-the-funnel-the-catalog-recuperer.md#adding-a-table-the-funnel-the-catalog-récupérer-waiting-list)).
- **"Parties du jeu" (Game parts)** (page of a table, after "Médias du jeu", Game media; closed to guests, door `sheet.parts`): one line per part, **Présent** (Present: files and size), **Reçu, à installer** (Received, to install), **Attendu** (Expected: waiting list), **Inutile** (Not needed: ROM of a table that uses none) or missing ("2 fichiers connus", 2 known files, when the VPS database knows some); then "Chercher sur le web…" (Search the web…) and **"Jeu : …"** (Game; "VPS" is never shown on screen).
  This VPS database game is the one the table points to (`tableGame`, `packages/core/src/gameparts.ts`): its origin or its `.info`, otherwise the only game its media come from, otherwise the media's deep search (name written in the table, file, folder, ROM, PuP-Pack, author), kept when it is certain (0.8 at least, well ahead of the next one, or confirmed by the media).
  Not certain: "Jeu : à choisir" (Game: to choose) shows the leads and "Chercher un titre…" (Search a title…); the choice is kept in the `.info` (`Info.VPSId`).
  Without a game, everything still works: the sites and the web search by the table's title.
- **A part: its proposals, from every source, at once**: opening a part starts the pre-search on all its sources (`partSources`) and each one redraws the screen when it arrives: the files the VPS database knows (one tile each, in the same list as the sites' ones: a page both know is a single tile, with the database preview when the site shows none; no action names VPS), the already downloaded files that fit, **VPForums** (signed in: otherwise "Se connecter à VPForums…", Sign in to VPForums…) and **VPUniverse** (the part's categories, `PART_SITE_NODES`: PuP-Packs 120, backglasses 33 and 189, colours 173, 101 and 174, altsound 113, ROM 15, POV 68, tables 82, music 112, topper 160 and 93, media 72).
  The proposals are tiles of the media gallery (thumbnail, site, popularity, "Autre jeu", Other game, last); one line per source says what it gave ("recherche…", searching…, "3 propositions", "rien pour ce jeu", nothing for this game, "connectez-vous…", sign in…, wait imposed by the site).
  Start on a proposal: its page opens in "Récupérer" (Get: VPS or site), the received file is filed for this table, then "Installer ce qui est reçu" (Install what was received); an already downloaded file opens the add plan.
  **"Chercher sur le web…"** (Search the web…) is always there.
  Then: "Tous les fichiers téléchargés…" (All downloaded files…, those that do not fit included), **"Chercher un fichier ou un dossier…"** (Look for a file or a folder…: Cyber Pinball's file picker, a file or a whole folder through "Prendre ce dossier entier" (Take this whole folder), since a PuP-Pack, sounds or colours are a folder; a folder that holds several, the whole `PUPVideos` or `VPinMAME\altsound`, is narrowed to the table's own from the names its script expects, otherwise "<partie> : lequel ?" (<part>: which one?) lists its subfolders, `partFolderPick`, `packages/core/src/installation.ts`), "Installer ce qui est reçu" (Install what was received), "Options du PuP-Pack" (PuP-Pack options), "Médias du jeu" (Game media) for the media, **"Réaffecter à une autre table"** (Reassign to another table: its files are moved there, named like it for a backglass, a point of view or own settings; what it had instead goes to the trash) and **"Retirer de la table"** (Remove from the table: confirmation, cursor on "Annuler", Cancel; Cyber Pinball trash, `<root>\trash\<date> Parties du jeu`; a library ROM stays there; removing the PuP-Pack also removes Cyber Pinball's `.vbs` that turned it on).
  Every addition goes through the add plan, **targeting this table**: a pack whose name does not say the game, or a `.vpx` (another version), goes to it; "Annuler" (Cancel) goes back to the part's screen.
- **Code**: [app/src/game-parts.ts](../../app/src/game-parts.ts) (screens), `routeReceived`, `repairWaitList`, `contentParts`, `partFits` in [packages/core/src/acquisition.ts](../../packages/core/src/acquisition.ts), `target` of `planImport` in [packages/core/src/tableimport.ts](../../packages/core/src/tableimport.ts).
  Tests: `packages/core/src/test/parties.test.ts` (two files from one page, each nature in its part, complete archive, nothing blocking, The Matrix case filed by itself, targeted plan, present parts).
